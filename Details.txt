Act as a Principal Full-Stack Engineer and UI/UX Designer. Build a complete, mobile-optimized Solar Installation & Maintenance CRM Web Application from scratch using React (Vite), Firebase (Authentication & Firestore), and Plain CSS with Tailwind utility animations where needed.

======================================================================
1. CORE OBJECTIVES & PERMISSION MODEL (THE YOUTUBE ACCESS MODEL)
======================================================================
The application serves two distinct user roles:

1. ADMIN / SUPER USER
   - Complete CRUD access to all solar projects, user accounts, and maintenance tickets.
   - Central control to toggle projects as "Showcase" items (publicly visible).
   - Global dashboard displaying business metrics (total kW capacity deployed, active maintenance tickets, upcoming service schedules, total client savings).

2. CUSTOMER / PROPERTY OWNER
   - Public/Showcase View: Can browse a public gallery of completed projects (showing city, system capacity in kW, environmental impact/savings, high-level photos) without exposing sensitive customer information.
   - Private "My Solar System" Dashboard: Upon self sign-up, entering a valid "Claim Code/Installation ID" links the user directly to their specific installation.
   - Deep-Dive Access: Customers can view ONLY their own project details (panel specifications, inverter serial numbers, warranty expiration dates, total energy/money saved metrics based on daily sunlight formulas, and historical service logs showing technician name, date, and cost).
   - Maintenance Ticket Raising: Ability to submit maintenance requests with problem notes and optional photo attachments.

======================================================================
2. USER ONBOARDING & ACCOUNT CLAIMING FLOW
======================================================================
1. Admin creates a new project document in Firestore with a auto-generated unique "Claim Code" (e.g., SOLAR-PUNE-8492).
2. Customer signs up via Email/Password on the public sign-up page.
3. Upon first login, if the customer has no linked project, they are directed to an "Enter Installation Claim Code" screen.
4. Entering the valid Claim Code links the project's ownerId to their Firebase request.auth.uid and unlocks their private dashboard.

======================================================================
3. DATA ARCHITECTURE & FIRESTORE COLLECTIONS
======================================================================
Design the database schema using the following collections:

1. `users` Collection:
   - uid (string, Primary Key matching Firebase Auth)
   - email (string)
   - name (string)
   - role (string: "admin" | "customer")
   - createdAt (timestamp)

2. `projects` Collection:
   - id (string)
   - claimCode (string, unique)
   - ownerId (string, nullable until claimed)
   - title (string, e.g., "10 kW Residential Rooftop")
   - city (string)
   - capacityKW (number)
   - installationDate (timestamp)
   - warrantyExpiryDate (timestamp)
   - panelModel (string)
   - inverterModel (string)
   - inverterSerialNumber (string)
   - tariffRatePerkWh (number, for savings calculations)
   - dailyAvgSunlightHours (number, default e.g., 5.5)
   - isPublicShowcase (boolean)
   - showcaseImage (string URL)
   - nextMaintenanceDate (timestamp)

3. `maintenance_logs` Collection:
   - id (string)
   - projectId (string)
   - serviceDate (timestamp)
   - technicianName (string)
   - workPerformed (string)
   - cost (number)
   - status (string: "Scheduled" | "Completed" | "Pending")
   - ticketType (string: "Routine Check" | "Panel Cleaning" | "Inverter Repair" | "Emergency")
   - customerNotes (string, optional)

======================================================================
4. TECH STACK & DESIGN REQUIREMENTS
======================================================================
- Front-End Framework: React (built with Vite)
- Routing: React-Router-DOM (v6+)
- Styling: Plain CSS for primary component structure + Tailwind CSS utility classes for responsive grids, flex layouts, and smooth transition animations.
- Icons: Lucide-React
- Charts: Recharts (for rendering calculated monthly/annual energy and money saved graphs)
- Backend & Auth: Firebase JS SDK (v10+) using Firebase Auth and Firestore.
- UI Experience: Mobile-First Responsive layout.
  * Mobile View: Sticky bottom navigation bar, card-based feeds, single-column dashboard.
  * Desktop View: Collapsible left sidebar, multi-column metrics dashboard, data tables for Admin lists.

======================================================================
5. STEP-BY-STEP DEVELOPMENT PHASES
======================================================================
Deliver the application across 4 distinct phases:

PHASE 1: Core Setup & Auth Architecture
- Initialize React (Vite) app structure, router setup, and `firebase.js` configuration.
- Implement AuthContext to manage logged-in user state, roles (`admin` vs `customer`), and session persistent storage.
- Create Login, Self Sign-Up, and Installation Claiming screens.

PHASE 2: Public Showcase & Customer Dashboard
- Build `/showcase` route displaying all projects where `isPublicShowcase == true` in a grid card layout.
- Build `/dashboard` route for logged-in customers displaying:
  * Key stats cards (System Capacity, Total Energy Generated estimate, Money Saved estimate, Next Service Due).
  * Panel & Inverter technical spec cards.
  * Service Timeline showing all `maintenance_logs` linked to their `projectId`.
  * "Request Service" modal form pushing new maintenance tickets to Firestore.

PHASE 3: Admin Command Center
- Build `/admin` protected route (inaccessible to non-admins via Firestore rules and React Router guards).
- Master Projects Table: Search, filter by city/status, edit project specs, toggle public showcase status, and generate new Claim Codes.
- Maintenance Dispatcher: Schedule new maintenance visits, assign technician names, set costs, and update ticket statuses.

PHASE 4: Security Rules & Logic Verification
- Provide production-ready `firestore.rules` enforcing that customers can ONLY query project documents where `resource.data.ownerId == request.auth.uid` or `isPublicShowcase == true`.
- Implement client-side formulas for estimated money saved: 
  `Total Saved = Capacity(kW) * Daily Hours * Days Since Install * Tariff Rate`.
